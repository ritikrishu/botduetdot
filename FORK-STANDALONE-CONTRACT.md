# Standalone app contract (working material — delete before merge)

Branch `feat/standalone-app` (from `feat/sidebar-spaces`, base `v0.1.9`). Goal: release this fork as an
independently named app — signed/notarized macOS desktop via GitHub Releases with auto-update, and an
Android app on Google Play — that never talks to T3 Tools Inc. services, uses none of their
identifiers/marks, coexists with the official app on the same Mac and phone, keeps the MIT notice, and
stays cheap to merge with upstream releases.

Decided: no T3 Connect (relay/Clerk), no push notifications, LAN/Tailscale pairing only. Name not chosen:
everything below is driven by one brand profile with placeholder values (`Placeholder` / `placeholder`).

Legend for decisions: **REPLACE** (brand value), **DISABLE**, **REPOINT** (owner-controlled target),
**KEEP** (internal or third-party), **OUT** (out of scope for v1). Priority: **P0** = app breaks, phones
home, or shares OS identity/data without it; **P1** = wrong app opened / wrong links / first-impression
branding; **P2** = cosmetic or rare path.

## 2. Brand profile design

### 2.1 Source of truth

New fork-owned module `@t3tools/shared/brand` (`packages/shared/src/brand.ts`, owner-editable inputs in

`brandStandalone.ts` holds the only values the owner edits: `name`, `slug`, `reverseDns`
(`io.github.ritikrishu.<slug>` — owner-controlled without buying a domain), `repository`, `siteUrl`.
`defineStandaloneBrand()` derives the rest (`appId = reverseDns`, `launchdLabel = appId + ".service"`,
schemes from slug, Play URL from package, …). `UPSTREAM_BRAND` holds **today's literals verbatim**, and
the T3 constants move into it (ingest host/key, manifest URL, hosted URL, repo) so seams reference
`BRAND.x` instead of inline strings — that lets standalone bundles drop them and makes the leak check
(§5.3) meaningful. Also exported: `resolveBrandProfile(id)`, `brandAppSchemes(brand)`,
`isBrandAppProtocol(protocol, brand)`, `desktopRendererOrigins(brand)`.

Invariant: with `T3CODE_BRAND` unset, every seam evaluates to the current upstream value (tested), so
upstream behaviour and existing tests are unchanged.

## 8. Risks / open questions (with recommendations)

   merge.

   headers, permission strings, installers, store listing. Pick screenshots that avoid residual copy;
   consider a later mobile sweep (31 files) via `BRAND.name`. Risk: a Play impersonation flag.

   thread links are dead outside the app. Later: an owner domain with a static "open in app" page. Thread
   links require a bare origin (`threadLinks.ts:10` builds the prefix from the origin), so a
   path-based GitHub Pages URL won't work.

   for the brand instead (`TriageService.prepare` fails with a clear message; CLI command hidden).
   Recommendation: repoint.

   auto-update. Repoint later if needed.
6. **Versioning** `X.Y.Z-<slug>.N` with electron-updater is UNVERIFIED → mock-update test before the first
   public release; fallback plain semver.
7. **Expo env inlining** of `EXPO_PUBLIC_T3CODE_BRAND` into workspace packages is UNVERIFIED → leak check on
   the Android bundle; fallback: mobile seams read `Constants.expoConfig.extra.brand` explicitly.
8. **DCE of the upstream profile** in branded vite bundles is UNVERIFIED → leak check; fallback: inject the
   profile only (no upstream fallback) when the define is present.
9. **Clerk SDKs stay linked** (desktop bridge always created; mobile plugin adds a `clerk://` callback
   filter). Inert without keys; removing them would mean large upstream edits. Verify no startup network.
10. **No passkey entitlements** → in-app browser Touch ID passkeys unavailable. Acceptable.
11. **Play review**: app access (server required), possible AI-generated-content policy questions (the app
    displays agent output from the user's own subscriptions; prepare review notes), data-safety wording,
    16 KB alignment, and `SYSTEM_ALERT_WINDOW`/legacy storage permissions in the merged manifest.

    gate in a follow-up if the CLI is ever distributed.
